# 030-用户审查确认流程

> 定义配方生成完成后，用户对完整方案进行最终审查确认的标准流程，确保交付前无遗漏、无错误。

---

## 目的

在所有规则执行完毕后（含022实用有效性验证），向用户呈现完整的配方方案，提供系统化的审查检查清单，确保用户逐项确认后才能导出交付。

---

## 触发器

**WHEN** 022-实用有效性验证 通过并获得用户确认后。

---

## 输入

- 所有前置规则的最终产出物（A/B配方、操作流程、科学依据、地域适配、添加剂说明及022报告；内部成本资料不进入审查文案）
- **022-实用有效性验证报告**（4维度评分 + 风险项 + 未覆盖问题）

---

## 行为

### 步骤1：组装完整配方方案

将所有前置规则的产出物汇总为一份完整方案：

```markdown
# 【{dish_name}】完整配方操作方案

## ⚠️ 重要提示（请务必阅读）
> 本方案依据公开研究、行业资料及可核实的供应商技术资料制定。
> 本方案尚未在该门店进行现场风味实测；预期效果属于有依据的设计判断，不应视为已实测结论。
> 食品添加剂须按适用食品类别、现行法规及供应商技术资料使用，不得超范围或超量使用。
> 实际风味可能受原料批次、设备、汤量和操作条件影响；本方案提供具体参数与适用边界。

---

## 📋 基本信息
- 菜品名称：{dish_name}
- 目标地区：{region}（{region_category}口味）
- 出餐场景：{scene}
- 配方总重：{total}g
- 总耗时：{time}分钟
- 难度等级：{level}

---

## 🥘 配方参数
{010-配方参数表}

## 🔬 科学验证结果
{011-验证结论摘要}

## 👨‍🍳 标准化操作流程
{012-完整操作流程 + 014-通俗原理}

## 🌍 地域适配说明
{013-调整了的调料 + 调整理由}

## 🧪 添加剂使用说明
{021-添加剂推荐（如有）}

## ⚠️ 避坑清单
{012-常见错误表}

## 🎯 实用有效性验证
{022-验证报告摘要：4维度评分 + 风险项}
```

### 步骤2：引导用户逐项审查

按以下顺序逐项确认：

```markdown
【最终审查——请逐项确认】

### 审查1：配方完整性 ✅/❌
- [ ] 原料清单是否齐全？有无遗漏？
- [ ] 每种原料的用量是否合理？
- [ ] 配方总重与各分项是否算术正确并符合本次目标投料基准？总重不要求与原配方相同。
> 如有问题请指出，我将回退到对应步骤修改。

### 审查2：科学性可信度 ✅/❌
- [ ] 配方参数是否经过了联网验证？
- [ ] 验证置信度是否可接受？
- [ ] 有无您存疑的配方参数需要进一步核实？
> 科学验证置信度：{X}%

### 审查3：操作可行性 ✅/❌
- [ ] 操作步骤是否清晰可执行？
- [ ] 每个关键节点的判断标准您是否理解？
- [ ] 时间/温度是否符合您厨房的实际情况？
- [ ] 常见错误您是否已知晓并会注意？

### 审查4：实用有效性（022验证结论复核） ✅/❌
- [ ] 场景匹配度：方案是否真的为您的场景（{scene}）量身定制？
- [ ] 操作真实可行性：在您的厨房条件下（设备/人手/空间）是否真的能做出来？
- [ ] 问题解决度：每个核心痛点是否都有明确设计回应、依据和风险说明？
- [ ] A/B两个版本是否逐项回应所有核心痛点，并明确各自依据和风险？
- [ ] 风险项是否已知晓并接受？
- [ ] 未覆盖问题是否需要回退补充？
> 022验证结论：场景匹配度{评分} | 操作可行性{评分} | 资源/流程适配{评分} | 问题解决度{评分}

### 审查5：A/B版本差异与比较目标 ✅/❌
- [ ] A、B两版是否都是完整配方，且存在有意义、可解释的差异？
- [ ] 每项差异是否直接回应顾客的核心痛点？
- [ ] 是否明确了比较指标、共同条件、预期差异和证据边界？
- [ ] 是否避免把未经实测的预期结果写成已验证结论？

### 审查6：地域适配 ✅/❌
- [ ] 调整后的口味方向是否符合当地客人偏好？
- [ ] 是否需要进一步微调某些调料用量？

### 审查7：添加剂安全性 ✅/❌
- [ ] 推荐的添加剂您是否理解其作用和用法？
- [ ] 安全上限和注意事项您是否已知晓？
- [ ] 您是否决定采用？（每项单独确认）

### 审查8：整体评价 ✅/❌
- [ ] 这个配方方案您是否满意？
- [ ] 是否可以直接使用了？
- [ ] 有没有任何需要修改的地方？
```

### 步骤3：处理审查结果

| 审查结果 | 处理方式 |
|---------|---------|
| 全部通过 | 进入 031-导出 Word/PDF |
| 某项不通过 | 明确问题→回退到对应规则→修改→只重新执行受影响的下游规则 |
| 多项不通过 | 逐项列出→按依赖顺序逐一回退修改 |

### 步骤4：审查通过确认

```
🎉 全部审查通过！

您的【{dish_name}】配方方案已完成，准备导出。

下一步：031-导出为 Word/PDF 格式。

是否现在导出？
```

---
⛔ **确认点**：以上为【030-最终审查确认】的完整产出。全部8项审查通过后，我将进入最后一步【031-导出Word/PDF】。

## 2026-10-26补充：最终审查边界

- 最终审查必须同时审查A、B两个完整版本及其设计差异。
- 不设置成本预算、成本合理性或单份成本审查项。
- 不要求配方提供者进行小锅测试；如需说明风险，只说明现场效果尚未实测，不得把实测作为交付前提。
- 最终数字一致性审计属于031导出前的强制技术门禁；030确认版本内容后，031仍必须执行该审计，不能以用户确认替代算术校验。

## 规则约束

- **禁止**：跳过任何审查项直接导出
- **禁止**：用户未明确确认时默认通过
- **要求**：每项审查必须用户明确回复确认
- **要求**：不通过项必须记录修改需求和回退路径
- **注意**：回退修改后必须重新审查受影响项（含022重新验证）

### 格式自检清单（输出前逐项检查）

- [ ] 8项审查逐项列出，每项有 ✅/❌ 复选框
- [ ] 每项审查有引导性提示文字
- [ ] 完整方案汇总A/B两版配方、验证、流程、适配、添加剂及022报告；不包含成本预算或成本核算
- [ ] ⚠️ 免责声明已置于封面后第一处正文

---

## 输出

- **完整配方方案**：所有规则产出物的汇总版本
- **审查记录**：8 项审查的逐项确认结果
