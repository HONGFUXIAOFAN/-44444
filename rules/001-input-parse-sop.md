# 001-输入解析SOP

> 解析用户输入的菜品信息，标准化为后续规则可消费的结构化参数。

---

## 目的

将用户自由文本输入（菜品名称、所在地区、出餐场景、特殊需求等）解析为标准化的结构化参数，供下游规则（010配方参数生成等）直接消费。

---

## 触发器

**WHEN** 用户提供菜品相关输入时。

**典型输入示例**：
- "我想做红烧肉，在四川绵阳开店，做正餐"
- "帮我生成一个鱼香肉丝的配方，我在广州做快餐"
- "卤猪蹄的配方，郑州夫妻店，外卖为主"

---

## 输入

### 必需字段

| 字段 | 说明 | 示例 |
|------|------|------|
| 菜品名称 | 用户想做的菜 | 红烧肉、鱼香肉丝、卤猪蹄 |
| 所在地区 | 用户店铺所在地（省市） | 四川绵阳、广东广州、河南郑州 |
| 出餐场景 | 快餐/正餐/外卖/小吃 | 正餐、快餐、外卖 |

### 可选字段

| 字段 | 说明 | 示例 |
|------|------|------|
| 目标客单价 | 用户期望的售价区间 | 20-25元、15元左右 |
| 特殊需求 | 用户的额外要求 | 少油、低盐、不加味精 |
| 用户身份 | 餐饮小白/店老板/厨师/夫妻店 | 创业小白 |

---

## 行为

### 步骤1：提取关键信息

从用户输入中提取以下结构化参数：

```yaml
dish_name: ""          # 菜品名称（标准化命名）
region: ""             # 省+市
region_category: ""    # 地域口味分类：川渝/江浙/粤闽/湘鄂/北方/其他
scene: ""              # 快餐/正餐/外卖/小吃
budget: ""             # 目标客单价（如有）
identity: ""           # 用户身份（如有）
special_requirements: [] # 特殊需求列表
```

### 步骤2：地域口味分类

根据所在地区自动判定口味偏好：

| 地区 | 口味特征 | 默认调整方向 |
|------|---------|------------|
| 川渝（四川/重庆） | 麻辣、重油、咸鲜 | 花椒↑、辣椒↑、油量↑ |
| 江浙（江苏/浙江/上海） | 咸甜、清淡、油少 | 糖↑、盐↓、油量↓ |
| 粤闽（广东/福建） | 清淡、鲜甜、原味 | 盐↓、糖微↑、香料↓ |
| 湘鄂（湖南/湖北） | 香辣、咸鲜 | 辣椒↑、盐适中 |
| 北方（京津冀/东北/山东） | 咸鲜、酱香、油重 | 盐↑、酱油↑、油量↑ |
| 其他 | 适中 | 保持基础配方参数 |

### 步骤3：出餐场景影响因子

| 场景 | 影响 |
|------|------|
| 快餐 | 操作流程需简化、出餐速度优先、成本敏感度高 |
| 正餐 | 口味优先、可接受复杂操作、成本敏感度中 |
| 外卖 | 需考虑配送途中口感变化（如酥脆类避免）、保温性 |
| 小吃 | 分量偏小、口味偏重、成本敏感度高 |

### 步骤4：输出标准化参数

向用户展示解析结果并确认：

```
✅ 已解析您的需求：
- 菜品：红烧肉
- 地区：四川绵阳（川渝口味——麻辣、重油）
- 场景：正餐（口味优先，可接受复杂操作）
- 用户身份：餐饮创业小白

请确认以上信息是否正确？如有需要调整的地方请告诉我。

```

## 2026-10-26补充：顾客问题与成功标准卡

在标准化菜品、地区、场景等参数之外，必须提取并随全流程传递以下字段：

- 顾客原始问题：尽可能保留用户原话，不把症状提前简化。
- 核心痛点清单：逐条拆分，例如香气不足、留香短、回味差、无记忆点；不得把多个痛点合并成一句笼统目标。
- 成功标准：说明顾客希望发生什么变化，以及每个痛点用什么可观察指标判断。
- 明确硬约束：只记录用户明确说不能改的事项、法律/食品安全边界和必要工艺条件。
- 可调整变量：原料种类、用量、比例、总重、添加剂、工艺时序和操作流程默认可调整。
- 交付模式：默认输出可执行书面方案和A/B两个测试版本；不得要求配方提供者先做现场试验才能交付。
- 证据边界：记录哪些结论有公开资料/供应商资料支持，哪些是合理推断，哪些缺少足够证据。

该卡是010、011、012、013、014、021、023、024、022、030和031的共同输入。后续模块不得把用户未指定的配方总重、原料数或原比例自行升级为硬约束。

## 输出

- **结构化参数块**：YAML 格式，供下游规则直接消费
- **用户确认**：等待用户确认后再传递给 010-配方参数生成

### 格式自检清单（输出前逐项检查）

- [ ] 结构化参数包含全部必需字段（dish_name / region / region_category / scene）
- [ ] 地域分类已按规则判定（川渝/江浙/粤闽/湘鄂/北方/其他）
- [ ] 场景影响因子已说明

---

## 注意事项

- **禁止**：跳过用户确认直接传递参数
- **要求**：即使输入信息不完整，也要明确列出已识别和缺失的字段，引导用户补充
- **要求**：地域分类不确定时，向用户确认而非猜测
- **注意**：用户可能一次提供多个菜品，需逐个解析并确认
