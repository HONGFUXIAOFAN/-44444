# 240反馈分析改进清单与执行记录

## 一、根因结论

1. 顾客核心问题没有成为贯穿所有模块的硬性设计目标；022原有“至少一项回应”标准不足以证明每个痛点都得到处理。
2. 配方精确性、总量核算和跨模块一致性被错误解释为保持原配方数字，导致优化变量被不必要地锁定。
3. 现有规则没有要求默认提供两个有意义差异、可公平比较的A/B完整测试配方。
4. 添加剂推荐的安全约束清楚，但与核心问题的目标驱动比较不足。
5. 020、022、030、031对成本和小锅测试的规定不一致；最终客户文案缺少统一内容边界。
6. CLAUDE.md、002和rule-plan.md的流程图、依赖顺序及规则编号没有同步，023和024在规划文件中被错误标为其他未来规则。
7. 031要求使用模板并运行self_check，但实际曾绕过该门禁；模板本身固定要求小锅测试，且未验证A/B版本与最终数值审计。
8. 没有独立的最终数值冻结与全文一致性审计，导致修改后的数值可能在重复引用、操作步骤、分装表和速查卡中不一致。

## 三、A/B最终交付要求

- A和B是同一顾客目标下的两个相近方案，不是两个完全无关的配方。
- 每个版本必须有完整精确配方；版本差异必须落实到配方数字或流程，不能只写在说明里。
- 每个版本独立核验科学性、食品安全、操作可行性和数字一致性。
- 给出公平比较条件、评价维度及选择依据；不声称未经实测的胜负结果。
- 用户可以自行测试或选择；这不是获得文档的前提。

## 四、最终数值审计要求

1. 优化阶段允许改变任一未被明确锁定的数字；不得为了维持原总重而拒绝合理调整。
2. 方案定稿后，对A和B分别建立唯一最终参数表。
3. 全文检索所有原料和数字引用，包括配方表、流程、添加剂卡、分装表、速查卡和重复说明。
4. 对每种原料核对最终值；有意分次加入时核对各次用量之和。
5. 重新计算各分项、每锅量、批次量、分装小计、比例和单位换算。
6. 任何数字改动后重新运行相关计算及全量一致性审计。
7. 数字审计通过后才允许调用模板导出；随后运行self_check。
8. A/B之间有意差异不算矛盾，但每个版本内部的重复数字必须一致。

## 五、已核查的规则冲突与修复点

- 022原有问题回应标准仅要求至少一个设计决策，需升级为逐项痛点映射。
- 020/022/030/031对成本和小锅测试的描述不一致。
- 030含成本审查和小锅测试建议；031模板免责声明也固定要求小锅测试。
- CLAUDE和002的流程入口与总览不一致；rule-plan.md将023/024错误列为尚未开发的其他规则。
- 031模板需要同步强制A/B方案、数值审计输入和最终文案禁项检查。
