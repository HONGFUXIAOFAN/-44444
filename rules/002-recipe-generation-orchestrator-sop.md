# 002-配方生成总控SOP

> 编排完整的配方生成全流程，协调各规则按依赖顺序执行，在每个节点汇总阶段性产出物，确保最终交付完整的配方操作方案。

---

## 目的

作为配方生成流程的"总指挥"，定义规则的执行顺序、衔接逻辑和阶段汇总节点，确保从输入到输出一气呵成，不遗漏任何环节。

---

## 触发器

**WHEN** 用户提供菜品输入，启动完整配方生成流程时。

---

## 2026-10-26全局优先级

所有阶段都服务于001确认的顾客问题与成功标准。原配方总重、香料粉总重、原料数量、比例和原流程均为可调整变量，除非用户明确锁定。默认最终交付A、B两个完整且有意义差异的配方版本。成本只在相关时内部分析，不进入最终客户文案。配方提供者无需先做实测；证据边界必须如实说明。031导出前必须完成每个版本的全文数字一致性审计。

## 完整工作流

### 流程图

~~~
用户输入
  ↓
[001] 输入解析 + 顾客问题/成功标准卡 ← 用户确认
  ↓
[010] 以痛点为目标生成A/B两版完整配方 ← 用户确认
  ↓
[011] A/B分别科学验证 ── [020] 可选内部成本/平替（仅成本目标相关）
  ↓
[012] A/B分别生成操作流程，共用步骤与差异步骤明确 ← 用户确认
  ↓
[013] 地域适配 ── [021] 目标驱动添加剂评估（两版分别更新）
  ↓
[014] 解释A/B差异、机制与证据边界 ← 用户确认
  ↓
[023] A/B分别跨模块一致性校验（P0门禁）
  ↓
[024] A/B分别整体科学协同性验证（P0门禁）
  ↓
[022] 每个核心痛点逐项映射 + A/B可比较性验证 ← 用户确认
  ↓
[030] 最终审查（无成本预算审查）← 用户逐项确认
  ↓
[031] 冻结A/B数字 → 全文数值审计 → 模板导出 → self_check
  ↓
交付Word/PDF（含A/B两版与比较标准）
~~~

### 分步执行说明

#### 阶段1：输入理解（001）
```
执行：001-输入解析SOP
产出：结构化参数（菜品名/地区/场景/特殊需求）
检查点：用户确认解析结果正确
```

#### 阶段2：配方核心生成（010 + 011；020按需内部运行）
~~~
执行：010以顾客核心痛点为目标，生成A/B两个完整配方版本 → 用户确认设计方向
执行：011分别验证A/B的科学依据、用量范围、安全与证据边界
可选：只有用户明确提出降本/预算/采购替代目标时，才运行020作内部成本/平替分析；其内容不进入默认客户交付。
检查点：
  - A/B两版是否完整且有意义差异？
  - 每个差异是否对应具体顾客痛点？
  - 配方数字与总重是否分别算术正确（不要求与原配方总重相同）？
  - 科学证据与推断是否明确区分？
~~~

#### 阶段3：操作流程+增强（012 + 013 + 021 + 014 并行）
```
执行：012-操作流程生成 → 用户确认
并行：013-地域适配 + 021-添加剂推荐
执行：014-通俗注入
检查点：
  - 操作步骤是否有精确参数？
  - 关键节点判断标准是否清晰？
  - 地域适配参数是否合理？
  - 添加剂推荐是否安全合规？
  - 通俗原理是否覆盖了所有关键步骤？
```

#### 阶段4：跨模块与实用性验证（023 → 024 → 022）
~~~
执行：023对A/B分别做010↔012↔014及添加剂引用一致性校验
执行：024对A/B分别做整体科学协同性验证
执行：022逐项核验全部顾客核心痛点，并检查A/B版本是否完整、可解释、可比较
检查点：
  - 每个核心痛点是否有明确设计回应、机制、证据与风险？
  - A/B差异是否落实到具体参数或操作步骤？
  - 场景、设备、人力、时间、批量换算是否可行？
  - 是否如实区分资料依据、科学推断与现场实测？
  - 未覆盖问题与风险是否清楚列出？
~~~

#### 阶段5：审查+导出（030 + 031）
```
执行：030-用户审查确认
产出：最终完整配方方案
执行：031-导出 Word/PDF
交付：用户拿到可直接使用的配方文件 ✅
```

## 全局检查清单

每个阶段结束后，总控检查以下项：

### 阶段1 检查
- [ ] 用户输入信息已完整解析
- [ ] 缺失信息已引导用户补充
- [ ] 用户已确认解析结果

### 阶段2 检查
- [ ] 配方参数表完整，无模糊词汇
- [ ] 科学验证置信度 ≥ 90%
- [ ] 验证问题项已处理
- [ ] 若成本目标明确，020内部分析已完成；不将成本内容带入最终客户文案

### 阶段3 检查
- [ ] 操作流程五阶段完整
- [ ] 关键节点有"正确 vs 错误"判断标准
- [ ] 地域适配参数已应用
- [ ] 添加剂推荐符合 GB 2760
- [ ] 通俗原理覆盖全部关键步骤

### 阶段4 检查（实用有效性验证）
- [ ] 场景匹配度已验证（✅/⚠️/❌）
- [ ] 操作真实可行性已验证（✅/⚠️/❌）
- [ ] 资源与流程适配已验证（不设默认成本/预算门槛）
- [ ] 问题解决度已验证（✅/⚠️/❌）
- [ ] 风险项已告知用户
- [ ] 未覆盖问题已诚实列出
- [ ] 每个顾客核心痛点均有具体设计回应
- [ ] A/B两版差异有目的、可解释、可比较
- [ ] 用户已确认验证结论

### 阶段5 检查
- [ ] 用户已逐项审查确认
- [ ] 最终方案无遗漏环节
- [ ] 导出前A/B分别完成全文数字审计并通过
- [ ] 文档使用指定模板并运行self_check通过
- [ ] 最终客户文案不含成本预算/核算表或强制实测要求

---

## 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 科学验证置信度 < 90% | 标注风险项，向用户说明，等待用户决定是否继续 |
| 用户要求修改配方参数 | 回退到 010，重新生成并重新验证 |
| 平替方案导致操作流程变化 | 自动更新 012 中相关步骤 |
| 网络搜索信息不足 | 诚实告知并标注证据边界，继续提供当前最有依据的方案；不得把用户实测作为交付前提 |
| 添加剂查询超出 GB 2760 | 明确告知不推荐，给出替代建议 |
| 022任一维度评分为 ❌ | 给出回退路径和修改建议，回退到对应规则修改后重新验证 |
| 022发现未覆盖问题 | 诚实列出，由用户决定是否需要回退补充 |

---

## 注意事项

- **禁止**：跳过任何用户确认节点继续推进
- **禁止**：在验证未通过时强制进入下一阶段
- **要求**：每个面向用户的阶段完成后等待确认；023/024/031等内部审计由AI自动执行，不要求用户代做
- **要求**：回退修改后必须重新执行被影响的所有下游规则

### ⚠️ 执行纪律

**你自动遵守规则——用户确认的是配方内容，不负责检查你是否遵守了规则流程。**
- 每一步必须按对应规则文件完整执行（联网验证、国标检查、格式自检）
- 每一步输出末尾必须明确询问用户确认
- 用户指出"没按规则走"= 你的失职，不是用户的事

---

## 2026-10-26补充：回退与数字冻结

任何配方、添加剂或流程修改都必须按依赖关系重新执行受影响的下游模块，尤其是023、024和022。A/B两版分别保留版本号与参数基准。只有030确认最终版本后，031才冻结数字并执行全文数值审计；在此之前不得为了方便审计而限制配方优化。

## 输出

- 最终完整配方方案（A/B两个完整版本、差异说明、比较标准、所有阶段验证结果；不含成本预算）
- 各阶段用户确认记录
