# 024-配方整体科学协同性验证

> 配方不只是各模块的机械拼凑。在单个参数经过011科学验证、跨模块一致性经过023校验后，必须对配方**作为有机整体**进行协同性验证——确保香料配伍合理、参数互恰、风味逻辑链完整、操作时序科学。

---

## ⛔ 强制执行声明

> **本规则是 P0 级强制门禁。024 未通过 = 方案不合格 = 禁止进入 022。**

---

## 目的

011 规则验证的是"每个参数单独看是否科学"——原料A用量有来源、原料B用量有依据。
但 **A+B+C 放在一起是否合理**，是不同层面的问题：

- 香料A和香料B的药性是否互补还是冲突？
- 参数X的调整是否会导致参数Y失效？
- 操作步骤的顺序是否有食品科学依据？
- 整个配方的风味逻辑链是否完整（前味→中味→后味→回味）？

本规则用多维度交叉验证回答这些问题。

---

## 触发器

**WHEN** 023-跨模块逻辑一致性校验全部通过后。

---

## 输入

- 010 规则产出的**配方参数表**（完整原料清单+用量）
- 012 规则产出的**标准化操作流程**
- 013 规则产出的**地域适配说明**
- 021 规则产出的**添加剂安全卡**
- 023 规则的**一致性校验报告**（已验证无矛盾）

---

## 行为

### 步骤1：五维度整体协同验证

对配方整体进行以下五个维度的系统性验证：

| 维度 | 验证内容 | 验证方法 |
|------|---------|---------|
| **香料配伍** | 所有香料的君臣佐使关系是否合理；有无药性冲突；剂量比例是否符合经典配比框架 | 联网搜索 ≥2 个来源，对照经典香料配伍理论 |
| **参数互恰** | 关键参数之间是否存在冲突：温度A是否会破坏原料B的有效成分；pH环境是否兼容所有添加剂；水分活度与防腐体系是否匹配 | 逐对检查冲突参数，联网验证相互作用 |
| **风味逻辑链** | 前味→中味→后味→回味的层次是否完整；甜/咸/酸/辣/鲜/麻的比例是否平衡；是否存在风味空洞 | 构建风味轮，检查各层次覆盖 |
| **操作时序** | 步骤顺序是否符合食品科学原理；等待/冷却/醒发时间是否充分；温度变化曲线是否合理 | 绘制操作时序图，联网验证关键时序 |
| **体系稳定性** | 整体防腐体系是否自洽（盐度+pH+水活度+防腐剂四重保障）；油脂抗氧化体系是否完整（天然+合成抗氧化剂协同）；乳化/悬浮体系是否稳定 | 联网搜索同类产品稳定性参数，交叉对比 |

### 步骤2：香料配伍专项（重点）

香料是配方协同性中最容易出问题的维度，单独深入验证：

#### 2.1 君臣佐使分析

```
主香（君）：{2-3种，定义风味底色}
辅香（臣）：{3-5种，丰富层次}
去腥（佐）：{1-2种，消除异味}
调和（使）：{1-2种，圆融各味}
```

每个角色必须有明确的"为什么选它"的科学依据。

#### 2.2 药性冲突检查

| 检查项 | 说明 |
|--------|------|
| 温/凉性冲突 | 丁香（温）+ 大量辣椒（热）是否过度？是否需要凉性香料平衡？ |
| 收/散冲突 | 有收敛性香料（如砂仁）同时有发散性需求时是否矛盾？ |
| 剂量比例 | 各香料用量比例是否符合经典配比范围（如八角:桂皮:花椒的经典比例） |

#### 2.3 处理方式协同

- 哪些香料需要"破壳/拍裂"才能出味？（如草果、白蔻）
- 哪些香料打粉后会变苦？（如丁香、砂仁）
- 哪些香料需要提前炒制/泡水/酒浸激活？
- **所有香料的处理方式合并在一起，是否构成一个可执行、不自相矛盾的整体方案？**

### 步骤3：风味逻辑链完整性

构建配方的风味轮，检查每个层次：

```
        前味（入口瞬间）
        /            \
    中味（咀嚼过程）    香气（鼻腔感知）
        \            /
         后味（吞咽后）
           |
         回味（余韵）
```

| 风味层次 | 本配方中的承担者 | 是否缺失 | 补充建议 |
|---------|----------------|:---:|---------|
| 前味（鲜/咸/酸） | {列出} | ✅/❌ | {如有缺失，建议补充} |
| 中味（主体风味） | {列出} | ✅/❌ | |
| 后味（油脂香/肉香） | {列出} | ✅/❌ | |
| 回味（甜/甘/麻） | {列出} | ✅/❌ | |
| 香气（挥发性香料） | {列出} | ✅/❌ | |

### 步骤4：参数互恰性校验

逐对检查可能存在冲突的关键参数：

| 参数A | 参数B | 潜在冲突 | 是否自洽 | 依据 |
|-------|-------|---------|:---:|------|
| 烫漂温度 80℃ | 叶绿素保护 | >85℃叶绿素降解 | ✅ | 在安全范围内 |
| pH 6.5 | 防腐剂效果 | 某防腐剂在酸性环境更有效 | ⚠️ | 需确认 |
| ... | ... | ... | ... | ... |

### 步骤5：多源交叉验证

对整体配方的科学性，必须通过至少 **3 种不同类型的来源** 交叉验证：

| 验证来源类型 | 最少数量 | 验证内容 |
|------------|:------:|---------|
| 学术/行业标准 | 2 | 配方框架是否符合该菜品的经典/行业做法 |
| 商业配方参考 | 1 | 香料组合是否与市场上成功产品有可比性 |
| 实操经验验证 | 1 | 操作时序是否在实际厨房中可行 |

## 2026-10-26补充：A/B两版分别完成整体协同验证

- A、B分别完成五维度协同分析；不得只验证一个版本后将结论套用到另一个版本。
- 对两版的有意差异逐项检查其与顾客痛点、风味逻辑、原料相互作用和操作时序是否匹配。
- A/B可在总重、原料种类和比例上不同；评价依据是科学性、问题回应与操作合理性，而非数字相同。
- 未经门店实测的效果必须标为预期或推断，不得称为实测结果。两版均通过证据与安全审查后，才进入022。

## 规则约束

- **禁止**：在存在 ❌ 维度的情况下强行进入 022
- **禁止**：多源验证少于 4 个来源（2学术+1商业+1实操）
- **禁止**：只做维度评分不给具体依据——每条结论必须有联网搜索结果支撑
- **要求**：香料配伍必须逐香料说明"为什么在这个配方里、扮演什么角色"
- **要求**：风味逻辑链缺失时必须诚实标注"本配方此层次偏弱"，并给出补充建议
- **要求**：整体评级为 C 或 D 时必须明确回退路径
- **注意**：这不是011的简单重复——011验证单个参数来源，024验证整体协同

### 格式自检清单（输出前逐项检查）

- [ ] 五维度验证每个维度都有评分+依据+风险等级
- [ ] 香料君臣佐使分析完整（每个香料有角色定义+选型理由）
- [ ] 香料处理方式合并后不自相矛盾
- [ ] 风味轮五层次检查完整（前中后回香）
- [ ] 参数互恰性至少检查 5 对关键参数
- [ ] 多源交叉验证 ≥ 4 个来源（2学术+1商业+1实操）
- [ ] 整体评级明确（A/B/C/D）+ 结论具体
- [ ] 存在❌时有明确回退路径
