# 餐饮配方自动生成器 规则规划文档

> **核心理念**：基于 DAP 框架（Decomposition-Aggregation-Prioritization）系统性规划领域规则体系，覆盖从输入解析到导出交付的完整生命周期。
>
> **使用场景**：
> - Administrator 开发领域规则前，基于本规划文档执行
> - 中小B端餐饮用户通过标准化流程获取科学配方方案

---

## 2026-10-26当前有效设计约束

- 顾客问题与成功标准优先；配方总重、原料数量和原比例是可调整变量。
- 默认A/B双版本；每版完整、差异有意义、单独验证。
- 023和024已是现行P0规则，不得列为未来待开发规则；执行顺序必须在022之前。
- 020为可选内部成本分析，不进入最终客户文案。
- 031导出前必须完成A/B全文数字一致性审计及模板自检。
- 交付不以配方提供者先做实测为前提；不得虚构实测结论。

## 2️⃣ 规则体系概览

### 整体架构

本领域规则分为总控SOP、核心生成、增强与验证、审查输出四类。依赖顺序以023/024在022之前、031最后执行为准。

~~~mermaid
graph TB
    S1[001 输入解析与顾客问题卡] --> P1[010 A/B配方设计]
    P1 --> P2[011 A/B科学验证]
    P1 -. 仅成本目标相关时内部运行 .-> E1[020 内部成本/平替]
    P2 --> P3[012 A/B操作流程]
    P3 --> E2[013 地域适配]
    P3 --> E3[021 添加剂评估]
    E2 --> P4[014 原理说明]
    E3 --> P4
    P4 --> V1[023 跨模块一致性]
    V1 --> V2[024 整体协同验证]
    V2 --> V3[022 问题解决度验证]
    V3 --> R1[030 最终审查]
    R1 --> R2[031 数值审计与模板导出]
~~~

## 3️⃣ 规则分类（Rule Decomposition）

### SOP流程类规则

| 规则ID | 规则名称 | 职责说明 | 对应核心概念 |
|:------:|----------|----------|-------------|
| 001 | 输入解析SOP | 解析用户输入的菜品名称、所在地区、出餐场景，标准化为后续处理的输入参数 | 配方+流程一体化输出 |
| 002 | 配方生成总控SOP | 定义完整配方生成流程的编排逻辑和各环节衔接规则 | 配方+流程一体化输出 |

### 核心生成类规则

| 规则ID | 规则名称 | 职责说明 | 对应核心概念 |
|:------:|----------|----------|-------------|
| 010 | 配方参数生成 | 生成菜品的完整原料清单和精确用量（克/ml），含配方总重和比例 | 配方+流程一体化输出 |
| 011 | 科学性联网验证 | 联网搜索多个来源交叉验证配方参数的科学性、真实性、安全性 | 配方真实性验证 |
| 012 | 标准化操作流程生成 | 生成从备料到成品的精确操作步骤（温度/时间/关键节点判断） | 标准化操作流程 |
| 013 | 地域口味适配 | 根据用户所在地区饮食习惯调整配方中咸/甜/辣/麻/油量参数 | 地域口味适配 |
| 014 | 科学原理通俗化注入 | 用通俗语言解释配方关键步骤背后的食品科学原理 | 科学原理通俗化 |

### 增强补充类规则

| 规则ID | 规则名称 | 职责说明 | 对应核心概念 |
|:------:|----------|----------|-------------|
| 020 | 可选内部成本与平替分析 | 仅在成本目标相关时进行内部分析，不进入最终客户文案 | 内部辅助 |
| 021 | 添加剂合理推荐 | 目标驱动评估合规添加剂与复合调味料，附带商品资料和安全说明 | 添加剂合理推荐 |
| 022 | 实用有效性验证 | 对每个顾客痛点逐项核验，审查A/B可比较性 | 问题解决度 |
| 023 | 跨模块逻辑一致性校验 | A/B分别核验010↔012↔014及数字引用 | 一致性校验 |
| 024 | 配方整体科学协同性验证 | A/B分别验证配伍、参数互恰、风味链与操作时序 | 整体协同 |

### 审查输出类规则

| 规则ID | 规则名称 | 职责说明 | 对应核心概念 |
|:------:|----------|----------|-------------|
| 030 | 用户审查确认流程 | 定义关键步骤的用户审查节点和确认机制 | 用户审查确认 |
| 031 | 导出Word/PDF | 将审查通过的完整配方方案导出为标准文档格式 | 配方+流程一体化输出 |

## 5️⃣ 开发优先级（Rule Prioritization）

### 优先级定义

| 优先级 | 判断依据 |
|:------:|----------|
| **P0** | MVP必须完成，直接支撑"输入菜品→输出配方"核心链路 |
| **P1** | 重要但非紧急，提升配方质量和用户信任 |

### 优先级清单

#### P0规则（核心链路与质量门禁）

| 规则ID | 规则名称 | 优先级依据 |
|:------:|----------|-----------|
| 001 | 输入解析SOP | 形成顾客问题与成功标准卡 |
| 002 | 配方生成总控SOP | 编排所有阶段并执行回退规则 |
| 010 | 配方参数生成 | 默认输出A/B两个完整、可优化版本 |
| 011 | 科学性联网验证 | 分别核验A/B的依据、用量与安全 |
| 012 | 标准化操作流程生成 | A/B均可执行，参数与配方一致 |
| 023 | 跨模块逻辑一致性校验 | A/B分别执行P0一致性门禁 |
| 024 | 配方整体科学协同性验证 | A/B分别执行P0协同门禁 |
| 022 | 实用有效性验证 | 所有顾客核心痛点逐项映射 |
| 030 | 用户审查确认流程 | 用户确认交付内容 |
| 031 | 最终数字审计与Word/PDF导出 | 数字审计、模板校验和self_check门禁 |

#### 增强规则（按需执行或提升交付质量）

| 规则ID | 规则名称 | 适用条件 |
|:------:|----------|----------|
| 013 | 地域口味适配 | 默认执行，结合目标客群调整 |
| 014 | 科学原理通俗化注入 | 默认执行，解释关键设计差异 |
| 020 | 可选内部成本与平替分析 | 仅在用户明确提出成本目标时运行 |
| 021 | 添加剂合理推荐 | 目标驱动评估，依法规和证据决定是否推荐 |

### 开发阶段规划

| 阶段 | 目标 | 规则 | 验收标准 |
|------|------|------|---------|
| **Phase 1**（核心质量链路） | 顾客问题驱动的A/B完整方案与科学验证 | 001, 002, 010, 011, 012, 023, 024, 022 | 每个痛点有回应；A/B完整且分别通过验证 |
| **Phase 2**（交付闭环） | 用户审查、最终数字审计与模板交付 | 030, 031 | 全文数值审计、模板校验与self_check通过 |
| **Phase 3**（增强能力） | 地域适配、原理说明、添加剂与可选成本分析 | 013, 014, 020, 021 | 添加剂合法、安全、商品信息可核实；成本不进入默认客户文案 |

## 7️⃣ 典型应用场景

### 场景1：生成一个完整的新菜品配方

**涉及规则**：001 → 010 → 011 → 012 → 013/021 → 014 → 023 → 024 → 022 → 030 → 031（020仅成本目标相关时内部运行）

**执行流程**：
1. 001 解析用户输入："红烧肉 + 四川绵阳 + 正餐"
2. 010 生成完整原料清单和精确配方参数
3. 011 联网交叉验证配方参数的科学性
4. 012 生成从备料到成品的标准化操作流程
5. 013 根据四川口味调整咸辣甜比例
6. 014 为关键步骤注入通俗科学原理说明
7. 023逐版检查配方、流程、原理与添加剂引用的一致性
8. 024逐版验证整体科学协同，022逐项验证顾客痛点和A/B可比较性
9. 030用户审查A/B两版、设计差异、风险与证据边界
10. 031冻结A/B数字、审计全文引用与总量，使用模板导出并运行self_check
（020仅当用户明确提出成本目标时作为内部辅助；最终客户文档不含成本预算或核算表）

**预期结果**：20-30 分钟内拿到可直接落地执行的完整配方操作方案。

---

### 场景2：添加剂安全性咨询

**涉及规则**：001 → 010 → 011 → 021 → 030

**执行流程**：
1. 001 解析："卤猪蹄能否加乙基麦芽酚？"
2. 010 调用卤猪蹄配方参数作为上下文
3. 011 联网验证乙基麦芽酚在卤肉中的合规性
4. 021 生成添加剂推荐：精确用量/使用时机/溶解方法/安全上限/注意事项
5. 030 用户确认理解安全事项

**预期结果**：拿到添加剂使用的完整安全说明书。
