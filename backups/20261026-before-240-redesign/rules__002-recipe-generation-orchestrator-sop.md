# 002-配方生成总控SOP

> 编排完整的配方生成全流程，协调各规则按依赖顺序执行，在每个节点汇总阶段性产出物，确保最终交付完整的配方操作方案。

---

## 目的

作为配方生成流程的"总指挥"，定义规则的执行顺序、衔接逻辑和阶段汇总节点，确保从输入到输出一气呵成，不遗漏任何环节。

---

## 触发器

**WHEN** 用户提供菜品输入，启动完整配方生成流程时。

---

### 分步执行说明

#### 阶段1：输入理解（001）
```
执行：001-输入解析SOP
产出：结构化参数（菜品名/地区/场景/特殊需求）
检查点：用户确认解析结果正确
```

#### 阶段2：配方核心生成（010 + 011 + 020 并行）
```
执行：010-配方参数生成 → 用户确认
并行：011-科学验证 + 020-成本平替
检查点：
  - 配方参数是否全部精确？
  - 科学验证是否通过？（置信度 ≥ 90%）
  - 成本是否在预算内？平替方案是否需要采用？
```

#### 阶段3：操作流程+增强（012 + 013 + 021 + 014 并行）
```
执行：012-操作流程生成 → 用户确认
并行：013-地域适配 + 021-添加剂推荐
执行：014-通俗注入
检查点：
  - 操作步骤是否有精确参数？
  - 关键节点判断标准是否清晰？
  - 地域适配参数是否合理？
  - 添加剂推荐是否安全合规？
  - 通俗原理是否覆盖了所有关键步骤？
```

#### 阶段4：实用有效性验证（022）
```
执行：022-实用有效性验证 → 用户确认
检查点：
  - 场景匹配度是否通过？
  - 操作真实可行性是否通过？
  - 商业有效性是否通过？
  - 问题解决度是否通过？
  - 风险项是否已告知用户？
  - 未覆盖问题是否已诚实列出？
```

#### 阶段5：审查+导出（030 + 031）
```
执行：030-用户审查确认
产出：最终完整配方方案
执行：031-导出 Word/PDF
交付：用户拿到可直接使用的配方文件 ✅
```

## 全局检查清单

每个阶段结束后，总控检查以下项：

### 阶段1 检查
- [ ] 用户输入信息已完整解析
- [ ] 缺失信息已引导用户补充
- [ ] 用户已确认解析结果

### 阶段2 检查
- [ ] 配方参数表完整，无模糊词汇
- [ ] 科学验证置信度 ≥ 90%
- [ ] 验证问题项已处理
- [ ] 成本核算已完成，高价原料已识别

### 阶段3 检查
- [ ] 操作流程五阶段完整
- [ ] 关键节点有"正确 vs 错误"判断标准
- [ ] 地域适配参数已应用
- [ ] 添加剂推荐符合 GB 2760
- [ ] 通俗原理覆盖全部关键步骤

### 阶段4 检查（实用有效性验证）
- [ ] 场景匹配度已验证（✅/⚠️/❌）
- [ ] 操作真实可行性已验证（✅/⚠️/❌）
- [ ] 商业有效性已验证（✅/⚠️/❌）
- [ ] 问题解决度已验证（✅/⚠️/❌）
- [ ] 风险项已告知用户
- [ ] 未覆盖问题已诚实列出
- [ ] 用户已确认验证结论

### 阶段5 检查
- [ ] 用户已逐项审查确认
- [ ] 最终方案无遗漏环节
- [ ] 文档格式正确导出

## 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 科学验证置信度 < 90% | 标注风险项，向用户说明，等待用户决定是否继续 |
| 用户要求修改配方参数 | 回退到 010，重新生成并重新验证 |
| 平替方案导致操作流程变化 | 自动更新 012 中相关步骤 |
| 网络搜索信息不足 | 诚实告知，标注置信度降低，建议用户人工验证 |
| 添加剂查询超出 GB 2760 | 明确告知不推荐，给出替代建议 |
| 022任一维度评分为 ❌ | 给出回退路径和修改建议，回退到对应规则修改后重新验证 |
| 022发现未覆盖问题 | 诚实列出，由用户决定是否需要回退补充 |

---

## 注意事项

- **禁止**：跳过任何用户确认节点继续推进
- **禁止**：在验证未通过时强制进入下一阶段
- **要求**：每完成一个步骤，等待用户确认后再推进到下一步
- **要求**：回退修改后必须重新执行被影响的所有下游规则

### ⚠️ 执行纪律

**你自动遵守规则——用户确认的是配方内容，不负责检查你是否遵守了规则流程。**
- 每一步必须按对应规则文件完整执行（联网验证、国标检查、格式自检）
- 每一步输出末尾必须明确询问用户确认
- 用户指出"没按规则走"= 你的失职，不是用户的事

- 各阶段用户确认记录
